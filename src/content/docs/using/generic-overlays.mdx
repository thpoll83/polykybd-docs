[Context-Aware Overlays](/using/overlays/) cover a long list of apps. For any other app,
PolyKybd collects what information it can by itself. There is nothing to install or configure.

Two things happen together:

- **Shortcuts the app publishes get an icon on their key** — Ctrl+S gets a floppy disk,
  Ctrl+B a bold *B* — read from the same accessibility information a screen reader uses.
- **The app's own icon appears on Escape**, on every modifier layer, confirming which app
  those icons belong to.

<Aside type="note">
**The Escape icon only appears when shortcut icons do.** If nothing could be read from the
app, the keyboard stays as it was.
</Aside>

<Aside type="note">
This is a fall-back, not a replacement. Where a hand-made overlay exists it always takes priority, key
by key — see [When an app already has artwork](#when-an-app-already-has-artwork).
</Aside>

## The icon on Escape

PolyKybdHost asks three sources in order and takes the first that is still recognisable when reduced to
a 1-bit 72×40 keycap:

1. **The icon the app itself ships** — the executable's own icon on Windows, the
   `.desktop` entry or icon theme on Linux, the bundle's icon on macOS. This is always correct,
   because it is the picture you already associate with that app.
2. **[Simple Icons](https://simpleicons.org/)** (CC0), the real brand mark where one exists.
3. **[Material Design Icons](https://pictogrammers.com/library/mdi/)** (Apache-2.0), which
   covers the Microsoft family that Simple Icons does not include.

## Icons for the app's shortcuts

Most applications already publish its shortcuts — that is how a screen reader can
announce them. PolyKybd reads the same information, matches each label to a concept, and
draws a small icon in the bottom-right corner of that key, clear of the key's own legend.

| Your platform | Where the shortcuts come from | Status |
| --- | --- | --- |
| **Windows** | UI Automation | Supported |
| **Linux** | AT-SPI2 | Supported; depends on the app's toolkit, see below |
| **macOS** | Accessibility API | Supported (host 1.1.0+), after a one-off permission |

### Linux: which apps work

What an app publishes depends on its toolkit, so on Linux it varies by app family:

| App family | Example | What PolyKybd gets |
| --- | --- | --- |
| **GTK3** with a menu bar | Mousepad | Every shortcut in the menu bar |
| **GTK4**, version 4.18 or newer | — | The shortcuts its menus show (host 1.16.6+; not yet confirmed on a real desktop) |
| **GTK4**, older than 4.18 | Ubuntu 24.04's GTK 4.14 | Nothing: these versions report every shortcut as blank |
| **Qt / KDE** | Kate | The shortcuts in its menus (host 1.16.6+) |

Nothing breaks when an app publishes nothing — the keyboard simply stays as it was,
Escape included.

<Aside type="note">
**Qt and KDE apps only publish shortcuts while the desktop's accessibility switch is on**, and
KDE Plasma leaves it off unless a screen reader is running. So PolyKybdHost turns it on the
first time it reads an app (setting **Shortcut → Enable Accessibility**, on by default). It
does not start a screen reader, and the switch stays on until you log out.

If an app was already open when PolyKybdHost started and its keys show no icons, restart the
app once.
</Aside>

<Aside type="tip">
**Shortcuts that appear later are detected too** (host 1.16.8+). Some apps only add items
like Save, Undo and Copy once a document is open — Kate's welcome page has none of them.
PolyKybdHost reads the app again when its window title changes, for example when a document
opens.
</Aside>

### macOS: one permission first

<Aside type="caution">
**macOS asks for permission once, and until you grant it PolyKybd cannot read any shortcuts.** The
Accessibility API returns an empty menu for an app that has not been trusted — which
looks exactly like an app with no shortcuts, so there is nothing on screen to tell you
which it is. Grant it in **System Settings → Privacy & Security → Accessibility**, then
restart PolyKybdHost.

⚠️ **The permission is per executable.** A terminal you launched the app from and a packaged
PolyKybd app are separate entries, so allowing one does not allow the other.
PolyKybd never opens the permission dialog
itself, so you have to go to System Settings.
</Aside>

### What gets an icon and what doesn't

An icon is drawn only when the shortcut's label maps to a concept the icon set covers —
Save, Copy, Paste, Find, Undo, Bold, Print and so on. A label the host cannot match
confidently gets no icon, because a plausible but wrong icon is
worse than none. Key combinations that the operating system uses (such as Alt+Tab) are skipped too.

## When an app already has artwork

If a hand-made overlay covers the app, it takes priority, but **per key**, not for the whole window.
Every key the artwork draws keeps exactly what its author intended, and the generic icons
fill only the keys it leaves blank.

Turn that off (see below) and an app with artwork shows exactly what was drawn for it and
nothing else.

## Working on another computer

In a [multi-machine setup](/using/multi-machine/) the app runs on one computer while the
keyboard is plugged into another. The shortcuts are read on the machine the app is actually
running on and sent across as text, so a forwarded app gets the same icons a local one does.

<Aside type="note">
This needs PolyKybdHost updated on **both** machines. An older forwarder still relays the
window title, so hand-made overlays keep working — but it sends no shortcuts, so a forwarded
app gets nothing generic until it is updated.
</Aside>

## Settings

All six are in **Settings…** in the tray menu. All are **on** by default except
**Generic → Overlays Add Shortcut Icons**.

| Setting | What it controls |
| --- | --- |
| **Generic → Overlays Enabled** | The whole feature. Off: no Escape mark and no shortcut icons for any app. |
| **Generic → Overlays Add Escape Mark** | Whether an app that already has artwork also gets its mark on Escape, when the artwork leaves Escape blank. |
| **Generic → Overlays Add Shortcut Icons** | Off by default. Whether such an app is also read for its shortcuts, with icons on the keys its artwork leaves blank. Reading a large app (a browser with a long page open) can take minutes, and its artwork already shows its main shortcuts. |
| **Shortcut → Icons Enabled** | Whether the focused app is read for its shortcuts at all. Off: nothing generic is drawn, since the Escape icon only accompanies shortcut icons. |
| **Shortcut → Icon Auto Fetch** | Whether the icon set may be downloaded. Off: icons already downloaded keep working; new ones are skipped. |
| **Shortcut → Enable Accessibility** | Linux only. Whether PolyKybdHost may turn on the desktop's accessibility switch so Qt and KDE apps publish their shortcuts. Off: only apps that publish anyway (GTK) are read. |

Two of them switch everything off: with **Generic → Overlays Enabled** or **Shortcut → Icons
Enabled** off, nothing generic is drawn and the other settings have no effect.

<Aside type="tip">
On a managed or offline machine the two you probably want are **Shortcut → Icons Enabled**
(the only one that governs reading another program) and **Shortcut → Icon Auto Fetch** (the
only one that uses the network).
</Aside>

## Privacy

Everything happens on your own computer. The host reads the focused app's shortcut labels
locally and never sends them anywhere; the only network request is for the icon set itself,
and it is cached after the first time. Nothing about which apps you use leaves the machine.

<Aside type="note">
For an app to look exactly right rather than only recognisable, use a hand-made overlay. It is a
template image plus a one-line mapping entry — [Create App Overlays](/howto/app-overlays/)
explains the steps, and it takes precedence over everything on this page.
</Aside>
