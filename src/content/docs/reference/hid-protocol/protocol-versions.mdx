## Protocol versions

The firmware advertises a `PROTOCOL_VERSION` (in the GET_ID string) that the host reads to decide
which commands to use. **The versions do not have to match.** The host connects to any keyboard
from v2 onwards and then enables each feature separately:

- **Same version** — everything works.
- **Keyboard older than the host** — it still connects, and only the features that keyboard is too
  old for are greyed out, with a *"some features need a firmware update"* hint.
- **Keyboard newer than the host** — the host asks what you want to do, defaulting to a safe
  connect that uses only the stable command set until you update the host app.
- **Older than v2** — refused, with *"Firmware too old… please update the keyboard firmware"*.
  The host cannot even list the keyboard's languages below that.

Selected milestones:

- **v2** — the **packed language list** (`0x1b`): a count byte plus one 2-byte ISO index pair per language, replacing the 4-ASCII-char legacy list. The legacy list (`0x08`) is retired and NACKs.
- **v3** — the **overlay-mapping** command (`0x15`) changed to **send no reply** (no per-chunk ACK), matching the other bulk overlay commands and removing a frequent source of stale replies.
- **v4** — **IDLE_STYLE** (`0x1c`): choose the idle anti-burn-in style (pulse / jitter).
- **v5** — a **brightness flags** byte on `SET_BRIGHTNESS` (`0x0d`): volatile vs host-auto.
- **v6** — a **per-bundle font-pack version block** appended to the GET_ID reply, so the host flashes only the bundles a keyboard is missing or behind on.
- **v7** — **SET_OS** (`0x1d`): the host tells the keyboard which OS it runs on, so modifier legends and shortcut hints match it.
- **v9** — **GLYPH_SCRIPT** (`0x1e`): override the letter/digit legends with an alternative script.
- **v10** — the glyph script became an **open-ended index** (an unknown script renders the normal legend), so new scripts need no protocol version change.
- **v11** — the **plain overlay upload** (`0x0a`) packs modifier + segment into one header byte, so a full 60-byte segment fits a 64-byte report exactly. The same version adds **REPLAY_ANIM** (`0x1f`), which plays the startup animation once.
- **v12** — **GUI combines with the other modifiers** for [app overlays](/howto/app-overlays/): `Cmd+Shift`, `Cmd+Alt` and the rest each get their own artwork instead of all falling back to the plain GUI icon, taking the addressable modifier variants from 9 to 16. The upload commands are unchanged, but the wider index space no longer fits the fixed 10-bit fields of `0x15`, so **SEND_OVERLAY_MAPPING_W** (`0x21`) was added alongside it.
- **v13** — **GLYPH_SIZE** (`0x22`): the [legend size](/using/legend-size/) — draw a key's main legend at one of three sizes, leaving the Shift/AltGr previews alone. Unlike the glyph script, the range is closed: the keyboard refuses a size it doesn't know, because an accepted-but-unrenderable size would look like a setting that does nothing.
- **v14** — **GET_LAYER_NAMES** (`0x23`): the keyboard names its own remappable layers, so the [layout editor](/using/keymap-editor/) labels its tabs from the connected keyboard rather than from a list built into the host. It reports the same layer count as the existing count command, so the editor can never draw a tab it has no name for.
- **v15** — **macros** (`0x24`–`0x26`): store text or a short key sequence on the keyboard and type it back with one key, with a short **label the keycap shows** so a row of macro keys shows `push`, `work mail`, `sign off` rather than M0, M1, M2. All three commands are enabled by a single protocol check, because a host that could read the macro list but not the bodies would show an editor for data it cannot read. See [Macros](/using/macros/).
- **v16** — **CRASH_RECORD** (`0x27`): the firmware records a hardware fault, an unexpected exception or a watchdog restart, restarts, and reports it on its next boot — on the console (which the host turns into an alert) and over this command. See [when the keyboard firmware crashes](/software/reporting-problems/#when-the-keyboard-firmware-crashes).
- **v17** — a **volatile** flag on `SET_UNICODE_MODE` (`0x14`): apply a unicode mode for this session only, without storing it. It exists for the Windows logon screen, where the host cannot yet tell *WinCompose is not installed* from *WinCompose has not started yet* — so it applies its first reading volatile and only stores the mode once it can tell the two apart. Before this, every logon on a WinCompose machine stored `Windows` and then wrote `WinCompose` back over it.
- **v18** — **IDLE_TIMEOUT** (`0x28`): how long the keyboard waits before it starts fading into the [idle style](/using/idle/#how-long-before-it-idles) becomes a setting — six presets from 15 seconds to 5 minutes — where it used to be fixed at 2 minutes when the firmware was built. 2 minutes stays the default, so a keyboard with default settings behaves as before. Like the legend size and unlike the glyph script, the range is closed: a keyboard refuses a preset it doesn't know, because an accepted one would be stored and then changed to a different duration without any message.
- **v19** — **SEND_PRC_OVERLAY** (`0x29`): [PRC](/reference/hid-protocol/image-encodings/#prc-predictive-range-coding) (Predictive Range Coding), a fifth keycap-image encoding that codes a typical icon to a payload of about 28 bytes. The host uses it per image, only where it saves a report; the older encodings stay.
- **v20** — **FILL_POOL_FROM_ICON** (`0x2A`): the [icon library](/reference/hid-protocol/overlay-mapping/#icon-library-fills). Icons the app templates share are stored in the keyboard's flash, and the host sends `(pool slot, icon id)` pairs instead of their bitmaps. A cold switch into a JetBrains IDE drops from 84 reports to 32. The GET_ID version block now reports the lower of the two halves' versions per bundle (firmware 1.11.5 changed this rule, see [Icon library fills](/reference/hid-protocol/overlay-mapping/#icon-library-fills)).
- **v21** — [mapping flags](/reference/hid-protocol/overlay-mapping/#mapping-flags) on **SEND_OVERLAY_MAPPING_W** (`0x21`): the prepare and enable steps of an app switch are sent in the mapping reports instead of separate `OVERLAY_FLAGS` reports. A switch between apps whose images the keyboard already holds needs about half the reports.
- **v22** — **REBOOT** (`0x2B`): restart both halves without saving anything, so the host's [boot-loop test](/software/reporting-problems/#catching-a-crash-that-happens-only-occasionally) can reboot the keyboard hundreds of times to catch a rare startup crash. Changing the handedness also reboots, but it writes the settings storage on every call.
- **v23** — a [dim flag](/reference/hid-protocol/overlay-mapping/#dimmed-icons) on **SEND_OVERLAY_MAPPING_W** (`0x21`): the keyboard draws the icons of a flagged report dimmed. The host uses it for a browser's shortcuts under a [website's overlay](/using/website-detection/#browser-keys-are-drawn-dimmed).
- **v24** (firmware 1.9.12, host 1.17.49) — a second byte on **SET_HANDEDNESS** (`0x19`) that sets or removes the [Rev.2 mark](/hardware/old-rev2-boards/) in the USB half's handedness stamp. A marked half becomes the main half only when the computer recognises it over USB, because a Rev.2 board passes USB power to both halves. `0` keeps the stored mark, so an older host that sends one byte cannot remove it.
- **v25** (firmware 1.9.15, host 1.17.82) — [keys without a legend](/reference/hid-protocol/overlay-mapping/#keys-without-a-legend) on **SEND_OVERLAY_MAPPING_W** (`0x21`): a pool slot sent plus 600 draws that key's icon on a cleared keycap. No new command and no new byte; an older keyboard refuses the value, so the host sends it only from v25.
- **v26** (firmware 1.10.2, host 1.19.58) — a second byte on **GLYPH_SCRIPT** (`0x1e`): the [placement](/using/glyph-scripts/#placement-centred-or-top-left) of the script's letters and digits, centred or top-left. `0` keeps the stored placement, so an older host that sets a script cannot reset it. A script byte of `0xFF` with a non-zero placement changes the placement only. An older keyboard ignores the byte and always centres, so the host sends it only from v26.
- **v27** (firmware 1.10.2, host 1.19.58) — font-pack layout v3: the [icon library](/reference/hid-protocol/overlay-mapping/#icon-library-fills) slot and the emoji slot grow from 256 KB to 512 KB, and the fantasy, Latin-big and icon bundles move. No new command. After the firmware update the host writes those three bundles once more if **Settings → Keyboard → Update on connect** is on; with it off, run `polyctl fontpack sync`. The host sends an icon library over 256 KB only from v27. A keyboard with older firmware keeps its old library, but the host fills icons from the library only when the keyboard holds the shipped version, so it sends those icons as normal images instead.
- **v28** (firmware 1.11.0, host 1.21.0) — the GET_ID reply adds a byte that says whether an Eden animation is running on the keycaps (the boot intro or the screensaver). The host waits to flash font packs until the animation has ended, so it does not draw legends over the animation. No new command. An older keyboard does not send the byte, and the host flashes at once, as before.
- **v29** (firmware 1.11.3, host 1.21.4) — **TAP_TERMS** (`0x2c`): the [tapping term and the Flow Tap term](/using/keymap-editor/#tap-hold-timing) of dual-function keys become settings, stored on the keyboard. They were fixed at 200 ms and 150 ms when the firmware was built, and those stay the defaults. Like the idle timeout, both ranges are closed: a keyboard refuses a value outside them. An older keyboard NACKs the command, so the host disables the tray entry.
- **v30** (firmware 1.11.6, host 1.21.14) — **TAP_TERMS** (`0x2c`) also reads and sets [Auto Shift](/using/keymap-editor/#auto-shift): on/off and the timeout (100–500 ms, 10 ms steps, default 180 ms). Auto Shift is off by default. A set with `[7..9]` all zero keeps Auto Shift, so a v29 host leaves it alone. A v29 keyboard ignores those bytes, so the host refuses Auto Shift values below v30. The same firmware adds [Caps Word](/using/keymap-editor/#caps-word), which needs no command.
- **v31** (firmware 1.13.0, host 1.22.4) — **AI** (`0x2D`) and **AI_CARD** (`0x2E`): [agent keys](/using/ai-agents/). The host sets a state per number key (the key's light) and a card per key (the keycap image in AI mode), and reads the keys pressed in AI mode. All of it is kept in RAM. The host sends the states every second; the keyboard clears them at USB suspend and after 30 seconds without an update.
- **v32** (firmware 1.13.0, host 1.22.4) — **KEY_ATTENTION** (`0x2F`): run the focus ripple of the first-run tutorial on any key, for example to point at a key in a program's tutorial. A new start replaces a running request; a cancel lets a running ripple finish. While a request runs, the ripple for a waiting agent waits.
- **v33** (firmware 1.13.4, host 1.22.16) — **COMBOS** (`0x30`): runtime combos (2 to 4 keys pressed together send one key) and tap dances (`TD(0)`..`TD(15)`: one key that sends a different key on tap, hold, double tap and tap-then-hold), set from the host and stored in the keyboard's flash. Each half keeps its own copy, and a commit confirms only once the other half has stored it.
- **v34** (firmware 1.13.4, host 1.22.16) — **KEY_ATTENTION** op 2 **GUIDE**: the ripple walks along a path of layer keys to a target layer. It rings the step on the active layer, moves when you hold a layer key and moves back when you let go, and ends when the target layer is active, when its ripples run out, or on a cancel or a new start. A step on the target layer, two steps on one layer or a key without a display NACKs. The host's [MIDI guide](/using/midi/#first-time-guide) uses it.
- **v35** (firmware 1.13.7, host 1.26.0) — **HOST_TUTORIAL** (`0x31`): the host's [tutorials](/using/tutorials/) put two lines on the status displays, darken every key but the ones a step is about, end with the reveal wave, and ask the keyboard to watch for a key, a keycode or a layer. The host polls the matches at least every few seconds; after 10 s without a report the keyboard ends the session and lights all keys again. Both halves show the text and the spotlight. An older keyboard NACKs the command, and the tutorial then rings keys only and every step ends with Next.
- **v36** (firmware 1.13.9, host 1.27.6) — **AI** op 1 gets 3 more bytes: the page shown, the page count and a counter of agents that finished on another page. Esc shows the page ("Next 1/2"), and the AI key ripples when an agent on another page waits or when the counter changes. Leaving AI mode with more than one page records event `13`, and the host goes back to page 1. Page count `0` means no pages: the page must then be `0`, and the keyboard keeps the v35 behaviour. An older host sends these zeros. With a page count above `0`, a page not below it NACKs; a page count of `0` with a page other than `0` NACKs too.
- **v39** (firmware 1.13.40, host 1.28.49) — four more [QMK keymap report ids](/reference/hid-protocol/message-formats/#qmk-keymap-commands): the [key lighting](/using/rgb-lighting/#from-the-host) (on/off, brightness, effect, speed, colour) on `0x07` / `0x08`, the uptime and the switch matrix on `0x02`, and device indication on `0x03`, with the ids and layout of the VIA protocol. The keyboard keeps lighting changes until it restarts. The switch matrix shows which keys are down, so it answers only while debug mode is on. Firmware before v39 sends no reply to these ids, so the host uses them only from v39.

<Aside type="note">
Not every version number above is a separate feature listed here — the list highlights the
milestones that changed the command set. Host and firmware are still released together at the
same `PROTOCOL_VERSION`, so keeping both current is the simplest way to have everything available —
but a version mismatch disables only the newer features, and the keyboard still connects.
</Aside>

<Aside type="tip">
Run PolyKybdHost with `--dev 2` to log the raw HID traffic — the easiest way to see these commands and their ACK/NACK responses as they are sent.
</Aside>
